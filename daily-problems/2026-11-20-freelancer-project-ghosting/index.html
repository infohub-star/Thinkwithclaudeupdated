Why do freelancers ghost projects after partial payments without accountability systems?

Small businesses pay a freelancer an advance and then the freelancer goes silent, with no record and no recourse. Here's "Milestone Lock", a deal-room that ties every payment to a delivered, checked milestone, buildable with Claude in a weekend.

Written by Shantanu Anand, AI Trainer & Consultant · 20 November 2026

B2B ServicesItch Score 76Build time: a weekend

The problem

Who feels it: Founders, small agencies and small businesses (MSMEs) that hire freelance designers, developers and marketers through WhatsApp, LinkedIn or referrals. They pay 30 to 50 percent upfront on a chat message, have no written scope, and lose both the money and the weeks when the freelancer stops replying. Honest freelancers feel the other side of it: clients who hesitate to hire them at all.

  • The talent pool is large and growing. NITI Aayog estimated 7.7 million gig workers in India in 2020-21 and projected 23.5 million by 2029-30 (NITI Aayog policy brief).
  • Most deals happen off-platform. A 2023 report found 68% of Indian freelancers rely on social media to find work (Business Standard), which means no escrow, no contract and no dispute process by default.
  • Trust is the stated barrier. Indian writers on the freelance market describe client hesitation around reliability and accountability as a core reason businesses avoid freelancers (YourStory).
  • Milestone payments are the known fix, but mostly inside marketplaces. Guides for Indian freelancers explain milestone payments as releasing money per agreed deliverable (Xflow); global platforms offer this for off-platform clients too (Upwork Direct Contracts).

Who's already working on it

Upwork, Fiverr and Freelancer.in protect payments inside their marketplaces, and Upwork Direct Contracts extends milestone protection to outside clients. Invoicing tools such as Refrens help freelancers chase payment, which is the opposite direction. We didn't find an India-first, rupee and UPI-native tool that gives a WhatsApp-hired freelancer and client a shared scope, milestone escrow and a delivery check.

The solution idea

"Milestone Lock" turns a WhatsApp project chat into a signed scope with milestones, holds each payment in escrow, and releases it only when the client approves a checked deliverable.

Chat-to-scopePaste the WhatsApp or email thread; it drafts a one-page scope with deliverables, dates and acceptance criteria for both sides to e-sign.
Milestone escrowThe client funds each milestone through a licensed escrow or payment partner; money moves only on approval or after a fixed review window.
Delivery checkEach submission is compared with the acceptance criteria, and a plain checklist shows what is done and what is missing.
Silence alarmIf the freelancer misses a check-in, both sides get reminders, and after a set gap the unfunded milestones are cancelled and unused money refunded.
Track recordCompleted milestones build a verified delivery history that freelancers can share with the next client.

Weekend build plan

  1. Saturday morning — scope test set: Collect 10 real project chats from founders you know. Write the scope-writer skill and hand-write the ideal scope for each as a test set.
  2. Saturday midday — prototype: Ask Claude for an artifact showing the deal-room flow. Show it to three founders and three freelancers.
  3. Saturday afternoon — chat-to-scope: Use the starter prompt in Claude Code to build thread upload, scope extraction and the e-sign page. Run the test set.
  4. Saturday evening — milestones: Add milestone creation, funding status and the review window as plain code with unit tests.
  5. Sunday morning — payments: Integrate a licensed escrow or marketplace-payments partner in sandbox mode. Never hold funds yourself.
  6. Sunday afternoon — delivery check and alarms: Add the deliverable checklist and a scheduled task for check-in reminders.
  7. Sunday evening — pilot: Run five live projects between founders and freelancers you know, and record every dispute and how it ended.

Starter prompt for Claude Code

Build a Next.js + TypeScript + Postgres web app called "Milestone Lock" for Indian clients and freelancers.

Flow: client pastes a WhatsApp or email thread -> Claude API extracts a scope as JSON
(deliverables, milestones with amount and due_date, acceptance_criteria, revision_limit)
-> both parties edit and e-sign -> client funds milestone 1 via the payments partner's sandbox API
-> freelancer submits a deliverable (file or link) -> Claude compares it with acceptance_criteria and returns a checklist
-> client approves or requests changes within a 5-day review window; no response = auto-approve.

Rules:
- Never invent scope items; every item must quote the source message it came from, or be marked "added by user".
- All money states (funded, released, refunded) are deterministic code with unit tests, never model output.
- Funds are held only by the licensed partner; the app stores status, not money.
- Daily job: if a freelancer misses two check-ins, notify both sides; after 7 days, offer cancellation and refund of unreleased milestones.

Start by proposing the schema and file structure, then build thread import and scope extraction first, with a test script over /fixtures.

Monetisation

Suggested pricing, not yet validated.

  • Free: one project with up to three milestones.
  • 2% of milestone value, capped at Rs 1,500 per project (not validated).
  • Rs 1,999 a month for agencies running many freelancers.
  • Channel: co-working spaces, startup communities and design or developer collectives.

Riskiest assumption, and how to test it

Assumption: Clients and freelancers who already deal informally on WhatsApp may not accept the friction of signing a scope and funding escrow for small projects.

Test first: Before building payments, run 10 real projects through a manual version: Claude drafts the scope, both sides sign a PDF, and the client pays milestones through an existing escrow service. Count how many pairs finish with the flow. A reasonable bar: at least 7 of 10 finish, and both sides say they would use it again.

Holding customer money in India is regulated, so use a licensed escrow or payment aggregator partner rather than holding funds yourself. Check with a lawyer before launch.
